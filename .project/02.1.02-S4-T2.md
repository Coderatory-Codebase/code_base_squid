# 02.1.02-S4-T2 — Invalid invitation server-rendered surface

Implemented the feature-owned invalid-link presentation with the required one-sentence
safe wording. It is now wired into the workspace invitation acceptance page for malformed
tokens and the common `error=invalid` response returned by the accept action. Unknown,
expired, already-used, revoked and email-mismatch cases share that same server-rendered
message. Added a markup regression test.

The route still uses the existing organization-invitation persistence flow; it is not yet
connected to Identity's `user_invitations` collection. A real token lookup and journey
case remain unverified until those flows are unified.

Status: **partial**.
