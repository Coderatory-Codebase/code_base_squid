# 02.1.02-S1-T5 — Invitation view budget measurement

## Contract

The pending invitation view must run against a seeded workspace at target volume,
record p95 across 200 requests, compare against the stated budget, name the serving
index, and commit a dated measurement.

## Plan

1. Create a reproducible benchmark entry point and explicit environment contract.
2. Seed exactly the required workspace-volume fixture through the feature boundary.
3. Capture p50/p95/p99 and the query explain-plan index once Docker/Testcontainers
   Mongo is available.
4. Commit the measured result; do not fabricate a measurement from mocks.

## Blockers discovered

1. Docker Desktop/Compose and a local `mongod` executable are unavailable. The required
   real-Mongo seeded fixture, transactions, and explain-plan inspection cannot run.
2. The API bootstrap does not expose the invitation-list route used by the web surface.
   Without an authenticated principal/policy boundary, a 200-request view measurement
   would benchmark a not-found response rather than the Story behaviour.
3. No seed runner, Testcontainers setup, or k6 installation is present in the repository.

## Required environment to continue

- Docker Desktop running (Testcontainers-compatible) with access to pull MongoDB images.
- The predecessor scoped-gateway/principal/policy/clock contracts composed into the API.
- A seed fixture with 200 pending invitations in one workspace and a separate tenant for
  isolation checks.
- k6 available to execute and record the 200-request measurement.

No p95 or serving-index result is recorded because no real measurement has run.
