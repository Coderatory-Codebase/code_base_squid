# 01.1.03-S2-T1 — Organization settings schema

## Implementation

- Kept settings in the existing `organizations.settings` field, as the Story Architecture
  record specifies; did not create a parallel collection.
- Replaced the settings `Mixed` schema with typed fields for time zone, week start, date
  format, and workspace setup rule. Unknown existing settings keys remain preserved.
- Added an explicit `version` field for optimistic concurrency. `deletedAt` and Mongoose
  `updatedAt` timestamps already existed on the organization document.
- Added `features/workspace/integrations/migrations/20261007-organization-setting.ts` to backfill
  `version: 1` on legacy organizations and remove only that field on rollback.

## Existing architecture reused

- **Step 2 complete:** the settings view filters by `workspaceIds` and `deletedAt` and
  projects `settings`; `workspace_settings_live_cover` is the matching compound index.
  Its winning-plan use is recorded in
  `servers/api/performance-results/organization-settings-2026-10-07.json`. The card's
  `{ workspaceId, organizationSettingId, updatedAt }` index refers to fields absent from
  this repository's organization model and query, so duplicating it would not serve the
  access pattern.
- **Step 6 complete:** the existing `organizations` collection is explicitly allow-listed
  in `servers/api/tests/collection-allow-list.test.ts`. This repository has no
  `architecture/collections.json`, so no duplicate collection or parallel allow-list was
  introduced.

## Step 5 — migration on a restored copy

- Took a logical snapshot of two legacy organization documents and the settings index in
  one disposable database, restored them into a separate disposable database, then ran
  `up` and `down` against that restored copy.
- `up`: both missing versions became `1` in **1.95 ms**.
- `down`: both migration-added version fields were removed in **1.17 ms**.
- Verified both documents and settings survived, the live/deleted states were unchanged,
  and `workspace_settings_live_cover` remained present after rollback.
- This was an isolated in-memory restored-copy exercise; no configured or persistent
  MongoDB database was used.
- Acceptance test cases and CI were not run, per the current work instruction.
- Updated the Workspace module contract and runbook with the settings schema, migration
  behavior, and restored-copy rehearsal requirement. The repository has no generic
  migration runner; deployment must use its approved database-migration process.
- Added the imported-card/index/allow-list mismatch to `.project/BACKLOG.md` for follow-up
  if the data model later gains a separate settings-history collection.

## Remaining architecture mismatch

The task card's sample index fields and `architecture/collections.json` do not exist in
this repository's Story Architecture. Steps 2 and 6 are satisfied by the equivalent
existing index and model allow-list; revisit the card references if the data model or
settings history query changes.
