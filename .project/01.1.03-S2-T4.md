# 01.1.03-S2-T4 — Organization settings update action and route

## Implemented

- Expanded the Zod patch schema to validate all four organization settings and the expected version.
- Added a server action that validates input, reads the HTTP-only session cookie, forwards the update, maps success/conflict/failure to a typed result, and revalidates the settings page after success.
- Added the public Next.js `PATCH /api/workspace/organization-settings/:organizationId` route.
- Added the authenticated API `PATCH /organizations/:organizationId/settings` route and Workspace updater. It resolves the target organization's actor, attaches the owner policy decision to the command, and performs an optimistic version update.
- A stale version returns `409` with the latest normalized settings and version when the organization still exists.
- The mutation is tenant-scoped to the authenticated owner and live organization, and its compare-and-set filter includes the expected version. It updates the existing `organizations` collection; this task introduced no collection or allow-list entry.
- The organization boundary signal identifies settings updates with `feature=organization-settings` and `operation=update`; the Grafana dashboard now charts update outcomes and p95. Proposed 5% error-rate/700 ms p95 thresholds and the update runbook await on-call ratification.
- No new interactive surface is introduced by this server action/API route task, so keyboard-walk evidence is not applicable here.
