# 01.1.03-S2-T3 — Organization settings policy binding

## Implementation

- Added the centrally named `organization.settings.update` ability under the API Access
  feature and bound `workspace.organization-settings.update` to it in Workspace policy.
- Added an injected policy evaluator that resolves the caller's workspace actor context;
  only a non-guest owner is allowed to update organization defaults.
- Added refusal coverage for a member without owner rights, a guest, and an API key, plus
  command-bus checks for a missing decision and for an owner allow decision.
- The settings mutation handler is introduced by the dependent server-action task; this
  policy binding is ready for that handler to use.
- Updated the Workspace module contract and runbook with the owner-only command policy,
  command-bus integration requirement, and refusal troubleshooting. No collection,
  background job, or interactive surface was added, so those conditional DoD items are
  not applicable to this change.
