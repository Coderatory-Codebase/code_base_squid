## Task understanding

Implement deterministic Workspace-domain decisions for the 30-day scheduled purge: reject invalid lifecycle snapshots, wait until the scheduled deletion date, emit a `WorkspaceDeleted` intent once per workspace using a stable idempotency key, wait for every required module/workspace confirmation, expose identifier/time-only trace entries, enforce/report the 24-hour start/completion budgets, and flag a scheduled deletion older than 31 days. The rule does not publish events or mutate persistence; those belong to the outbox, clock/identifier, Mongo and module-consumer contracts.

- Write tests first; cover every AC, including refusal cases; run the domain boundary check.
- Squid names Vitest, but this repository's API package is explicitly configured for `node:test`; follow the repository runner rather than adding a second runner without architectural justification.
