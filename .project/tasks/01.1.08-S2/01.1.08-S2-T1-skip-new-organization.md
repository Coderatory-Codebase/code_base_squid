# T1 work record: invitation-aware workspace bootstrap

Backlog task: `01.1.08-S2-T1` — “Skip the new organization when a first sign-in comes through an invitation.”

## Kept as T1 work

- Bootstrap resolves an invitation before creating a user; valid invitations accept membership without creating a new organization.
- No-invitation and explicitly chosen setup paths create the user, organization, `General` workspace, and owner membership inside one Mongo transaction.
- Mongo persistence uses the shared `users`, `invitations`, `organizations`, `workspaces`, and `memberships` collections. Invitation tokens are stored as SHA-256 digests.
- Unit tests cover valid, expired, and missing invitations; normal setup; verified-email forwarding; callback identity/token forwarding; and the rule that a failed invitation acceptance cannot fall through to organization creation. The opt-in Mongo integration test covers repeated acceptance and transaction rollback against a replica-set database.
- `workspace.sign-in.ts` is the small dependency-injected callback adapter; the real Auth provider must call it with a verified identity and the invitation token.

## Removed temporary dependency bridge

Removed the development-only email/password sign-in and sign-up UI, password/session storage, local invitation creation endpoint, mock bootstrap endpoints, and tests that only exercised those temporary routes. They stood in for the separate Auth/invitation-sending work and are not part of the assigned T1 implementation. No temporary auth UI or fake API remains in this branch.

The actual Auth callback/provider integration and invitation sender are still external dependencies. Wire the verified identity and invite token from that implementation into the kept bootstrap callback when it is available. Email delivery is not implemented here.
