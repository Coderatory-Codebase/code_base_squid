## Intended result

The shared event contract has a typed, versioned envelope and a registry of the Wave 1 event contracts. A new version can coexist with the previous version during the overlap period, so existing consumers can continue reading the version they support.

## Backlog scope

The task describes these implementation steps:

1. Add `src/kernel/events/envelope.ts` and `src/kernel/events/registry.ts`.
2. Register version 1 of the Wave 1 `Organization*`, `Workspace*`, `Member*`, `User*`, `Invitation*`, and `Team*` events.
3. Allow a producer to publish both versions during a version overlap.
4. Export the intended event contract types through the kernel's public entry point.

The envelope fields listed in the backlog are `id`, `type`, `version`, `workspaceId`, `actor`, `occurredAt`, and `payload`. The task is done when every event is typed and registered in the kernel and a new version exists alongside the old version.

## Architecture and ownership notes

Squid's architecture baseline identifies a **Shared Kernel** module owned by Platform. Its public surface is types and functions, including versioned event envelopes; it publishes no events of its own. Each producer owns its state change and writes its outbox record in the same transaction (ADR-007, ARC-002). The relay delivers at least once and consumers deduplicate by event ID (ARC-006). A breaking event change is a new version published beside the old one for one release (ARC-010). T1 must define the contracts and let producers form both envelopes; it must not create an event broker, outbox, relay, or module-specific command.

This repository has no existing kernel workspace. Its architecture policy puts reusable cross-workspace capabilities under `packages/*`, and `packages/types` is specifically for shared TypeScript/API types. The implementation owner is therefore a new `packages/kernel` workspace with a controlled public `index.ts`; event contracts live under `src/events/` there (the Squid conceptual path `src/kernel/events/`). This makes Shared Kernel ownership explicit without creating a root-level source tree or putting runtime registry behavior in the types-only package. No external runtime dependency is needed.
