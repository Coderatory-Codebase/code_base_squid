# 01.1.04-S3-T2 — Add the policy binding for this command and its refusal test

## Task context

- **Sprint:** Sprint 1 (Squid currently assigns this S3 story to Sprint 1)
- **Story:** 01.1.04-S3 — An organization owner uploads the organization’s logo
- **Task:** Add the policy binding for this command and its refusal test
- **Done when:** Binding registered; contract test asserts refusal for member, guest, and API-key principals that should not pass.

## My understanding

Both operations that change the logo lifecycle require real Workspace authorization: obtaining the scoped upload address and confirming/replacing/removing a logo. Only the organization owner may perform them. A member, guest, or API-key principal without the required ability must receive the Workspace `Forbidden` outcome, and a command without its policy decision must not execute.

## Squid implementation steps

1. Add the command ability in `src/modules/access/policy/abilities.ts`.
2. Bind the command to that ability in `src/modules/workspace/policy.ts`.
3. Add refusal contract tests for a member without rights, a guest, and an API key.
4. Assert the command bus rejects a command when no decision is attached.

- This branch has a read gateway taking `workspaceId`; it does not provide the production member/owner principal, ability registry, policy binding, or command bus.
- The temporary demo session under `organization-branding-demo` only authenticates a local demo read route. It cannot authorize logo updates.
- **Status: Blocked on the real dependency contract.** Do not implement a second auth/policy system or use demo credentials as owner proof. Once 01.4.04 is available, bind the new command to that contract and run these cases.
