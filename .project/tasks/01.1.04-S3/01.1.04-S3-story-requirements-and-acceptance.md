# 01.1.04-S3 — An organization owner uploads the organization’s logo

## Story understanding

An organization owner can upload, replace, and remove the organization logo. Members should see the logo in branding surfaces; when none exists they see the first letters of the first two words over the organization accent colour, or `#4B5563` when there is no accent.

## Requirements recorded in Squid

- **REQ-01.1.04-1:** Show the logo and accent colour in the organization list, organization details, and workspace header. Without a logo use the first letters of the first two words on the accent colour; without an accent use `#4B5563`.
- **REQ-01.1.04-4:** Only the owner may set the accent colour; it must be `#RRGGBB` and meet white-text contrast of at least 4.5:1; refuse lower contrast with measured ratio and support reset. Shared branding requirement; do not regress S2 behavior.
- **REQ-01.1.04-5:** Only the owner may upload, replace, or remove the logo. Allow PNG/JPEG up to 1 MB and dimensions 64×64 through 2048×2048; validate actual content, not filename. Refuse all other files with the reason.
- **REQ-01.1.04-6:** Logo text alternative is the organization name; failed image loads fall back to initials without a broken-image mark.
- **REQ-01.1.04-7:** Accent change/logo removal p95 <=300 ms; first organization-list page of 50 organizations with logos p95 <=700 ms.

## Architecture and security decisions in Squid

Squid records ADR-006, ADR-011, and SD-007 as resolving the architecture checks. Upload should go directly to the existing object storage via a presigned address; Workspace needs a command to issue the address and confirm the uploaded object because `updateOrganization (branding)` accepts values, not a file. Verify actual content and follow `threats-007` (short expiry and scoped key). Use the existing file bucket; do not add a storage service/component. At most one logo file of 1 MB per organization. The eight architecture checks flag a new Workspace-to-storage relationship, update command API, and shared-file security concerns; data/performance/operations/ADR/cost are recorded as no new concerns within the stated constraints.
