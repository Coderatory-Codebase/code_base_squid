# Temporary live login support for T2

This support lets the organization-branding page use the local API and MongoDB for a review/demo while the product's real authentication and organization-list dependencies are unavailable. It is isolated and opt-in. It is not production authentication and must be removed/replaced when the real dependency is merged.

## What was added

- API-only demo login and list endpoints in `servers/api/features/organization-branding-demo/`.
- The browser and API demo read from configured MongoDB; sample organizations are no longer returned by runtime code. This temporary login is still not the production principal/policy integration.
- Explicit API environment validation: the feature only starts when `TEMP_ORG_BRANDING_DEMO_ENABLED=true`, `NODE_ENV=development`, MongoDB is configured, and all demo credentials/workspace/session settings are present.
- A signed token with a four-hour lifetime. The configured workspace ID is embedded by the API; the browser cannot select or override it.
- Web login form at `/organization-branding-login`, backed by a Next server action. The action sends credentials server-to-server, and stores the returned token in an HttpOnly, SameSite=Lax cookie. The token is not sent to client JavaScript or local storage.
- Web server adapter in `apps/web/features/organization-branding/temporary-live/`; list requests include the cookie token and are not cached. With temporary mode disabled, the page shows an unavailable state instead of sample records.
- Read-only Mongo list query. No automatic inserts, seeds, updates, or deletes are performed.

## Enable locally

1. Keep the existing `MONGODB_URI` only in the ignored local `servers/api/.env`. Do not paste it into this document or commit it.
2. In that same local file, set `NODE_ENV=development`, then copy the `TEMP_ORG_BRANDING_DEMO_*` setting names from `servers/api/.env.example` and give them local values. Use a separate demo email/password (at least 16 characters) and a random session secret (at least 32 characters). Set the workspace ID to a row in the `workspaces` collection; the temporary API reader requires MongoDB.
3. Add `TEMP_ORG_BRANDING_DEMO_ENABLED=true` to ignored `apps/web/.env.local`. That file already has `NEXT_PUBLIC_API_BASE_URL`; keep its API URL pointed at the local API.
4. Restart both dev servers so they reload their environment files. Open `http://localhost:3000/organization-branding-login` and enter the demo email/password manually. No credentials are prefilled.

The API returns an empty list if the configured workspace has no matching Mongo records. T1's current model has no human-readable organization/workspace names, so Mongo IDs are displayed as labels. The reader does not write to MongoDB.

## Boundaries

- Development only; API validation fails if enabled in test/production.
- Secrets belong only in ignored local environment files. Never put demo secrets in source, browser code, docs, screenshots, or Git.
- No use of Squid tracker credentials. Use new local demo credentials.
- The API uses the configured workspace ID as its trusted principal and scopes Mongo reads to that workspace. No workspace ID comes from a URL, request body, or browser header.
- The temporary API endpoints are unauthenticated at transport level except for the explicit demo login/token flow; keep the API bound to loopback for local use and don't expose it publicly.

## Verify

From the repository root, run `pnpm --dir servers/api test`, `pnpm --dir servers/api typecheck`, `pnpm --dir apps/web test`, and `pnpm --dir apps/web typecheck`. For a live local review, enable the environment settings, restart both servers, log in, and confirm only the configured workspace's existing branding rows appear. If there are no rows, the expected state is the empty-list message.

## Remove after real auth/API merge

1. Remove the `TEMP_ORG_BRANDING_DEMO_*` entries from ignored local API/web env files and unset them in any local shell.
2. Remove `apps/web/features/organization-branding/temporary-live/`, `apps/web/app/(public)/organization-branding-login/`, and the temporary session API adapter (the folder under `apps/web/app/api/temporary-organization-branding/` if later added).
3. Remove `servers/api/features/organization-branding-demo/`, its `create-app`/`server` wiring and temporary API config/environment fields and validation.
4. Remove the temporary `listForWorkspace` Mongo adapter if the upstream owning gateway/catalog supplies that operation, then delete or supersede this support note. Keep the T2 view and UI; wire them to the upstream authenticated API adapter instead.
5. Search the repository for `TEMP_ORG_BRANDING_DEMO` and `temporary/organization-branding` to ensure no temporary references remain; run the API/web typechecks and required tests.
