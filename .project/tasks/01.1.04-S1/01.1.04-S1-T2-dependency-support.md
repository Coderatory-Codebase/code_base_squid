# T2 dependency support — authenticated Workspace branding reader

This prerequisite remains separate from the organization-branding view so it can be replaced or removed independently.

## Missing repository capability

- The scoped T1 gateway exists only inside `servers/api/features/workspace`.
- The app/API architecture forbids `apps/web` from importing the API server feature directly.
- The API has no organization-branding read route, and the web app has no auth/session capability that can provide a trusted `WorkspacePrincipal`.
- The list view also needs an organization listing contract; T1 currently exposes a scoped single-organization query.

Until these pieces exist, do not accept a raw `workspaceId` from a browser query parameter and do not hard-code a workspace ID into a live API request. That would defeat the T1 principal boundary.

## Temporary support created

- `apps/web/features/organization-branding/support/mock-gateway.ts` owns all demo records and the mock read contract.
- `demoWorkspacePrincipal` is used only by the demo route. The mock never connects to MongoDB and performs no writes.
- Fixture IDs cover a branded org (`org-acme`), absent logo and colour (`org-northwind`), failed image (`org-broken-logo`), unknown selection (empty), and an unavailable reader (unit-test input).
- An opt-in development-only login and read route now exist under `servers/api/features/organization-branding-demo/`. The web app uses a server action to exchange credentials with the local API, stores only a short-lived token in an HttpOnly cookie, and calls the read endpoint server-to-server. Both sides must explicitly enable `TEMP_ORG_BRANDING_DEMO_ENABLED=true`; the API rejects this mode outside development and requires MongoDB plus all demo settings.
- The API obtains the workspace ID from its local trusted environment, never from a browser parameter. The web session cookie is not readable by client JavaScript. No organization rows are seeded or written.
- The current T1 model does not contain organization or workspace display names. The temporary endpoint uses their IDs as labels and only shows IDs/logo/accent when matching Mongo records exist. It does not provide friendly names or create demo data.
- Setup, safety boundaries, checks, and removal steps are in `01.1.04-S1-T2-temporary-live-auth-support.md`.

## Replacement plan

When the owning authentication/session and organization catalog/read API are merged, remove this temporary auth feature, its routes/config keys and adapter, then replace it with the supported auth client and API contract. Keep the Server Component UI. Re-run the signed-in preview journey and 50-organization / 200-open p95 check against approved preview data; the current local mock-backed timing is documented in `01.1.04-S1-T3-acceptance-checks.md`.

## Update — 2026-10-06

The S1 web-owned mock organization gateway and its fixture-query route have been removed at the user's request. The fixture-backed Playwright journey and its browser performance result are retired; the old result is historical evidence only and must not be presented as current acceptance proof. Page-data tests now cover only pure name handling and empty/unavailable reader outcomes. Branded-organization acceptance and the 50-organization browser budget must be re-run against the real authenticated Workspace read path when that dependency is available.
