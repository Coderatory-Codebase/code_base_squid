# 01.1.04-S1-T1 — Extend the Workspace data gateway with the scoped query

## Task understanding

The organization-branding read must pass through the Workspace feature’s data gateway. It derives `workspaceId` from the caller’s principal, adds that scope after the organization and soft-delete filters, and does not accept a raw workspace ID from a caller. Its projection should be covered by the intended MongoDB index. A read using another workspace’s principal must return no rows.

## T1 implementation

- `servers/api/features/workspace/organization-branding.gateway.ts` builds the query from `WorkspacePrincipal` and appends `workspaceId` last.
- `servers/api/features/workspace/organization-branding.mongo-reader.ts` routes reads through the MongoDB integration boundary and provides an explain-plan assertion helper.
- `servers/api/features/workspace/tests/organization-branding.gateway.test.ts` covers workspace isolation, soft-delete exclusion, the index contract, and explain-plan result interpretation.
- `servers/api/features/workspace/tests/organization-branding.explain.ts` runs a read-only live explain check.
- The public feature API is `servers/api/features/workspace/index.ts`.

The repository’s MongoDB integration executes the query against the `workspaces` collection with a projection for organization ID, logo URL, and accent colour. No collection allow-list existed in this repository before this change, and this change does not add or alter one.

## Separate prerequisite support

The repository had no Workspace schema/model or branding index. To make the gateway runnable without waiting for another sprint, the provisional prerequisite model and compound covering index live separately in `servers/api/integrations/mongodb/workspace-branding.model.ts`; its exports are in the MongoDB integration barrel files. This support code is identified as prerequisite scaffolding and can be replaced by the owning team’s Workspace model when merged.

The index covers `workspaceId`, `organizationId`, `deletedAt`, `logoUrl`, and `accentColor`. Its declaration was provisioned in the configured development MongoDB. The explain plan then confirmed the winning and executed plans use `workspace_organization_branding_covering`. No records were inserted or deleted.
