# 01.1.04-S1-T3 — Automate the acceptance checks

## What I understood

Before handing over the organization-branding story, automate its four acceptance criteria and its keyboard-accessibility journey. Cover the branded organization, missing branding defaults, a broken logo request, and the 50-organization first-page performance budget. Include a permission refusal check. Keep test fixtures separate from product data and leave the test criteria unchanged.

## What I implemented

- Added Playwright configuration in `apps/web/playwright.config.ts`. It runs against a production build on port 3101 using the installed Microsoft Edge browser, independently from the developer's port-3000 server.
- Added AC1 browser journey and screenshot baselines for the directory logo and selected-workspace logo in `apps/web/tests/e2e/organization-branding.spec.ts-snapshots/`.
- Added AC2 integration coverage that loads Northwind through the server-side mock gateway and renders the view, asserting its `NT` initials, accessible name, and neutral `#4B5563` accent.
- Added AC3 browser coverage that blocks Acme's logo request, then checks the `AD` initials, Acme's `#1D4ED8` colour, accessible name “Acme Design”, and removal of the broken image element.
- Added an opt-in 50-organization load fixture to the web-owned mock gateway. It is available only when `ORGANIZATION_BRANDING_T3_FIXTURES=enabled` is set by Playwright and the test URL asks for `fixture=load`; it never selects a workspace from the URL.
- Added AC4 measurement for 200 page opens against a production build. The local p95 was **342 ms**, below the 700 ms limit.
- Added a keyboard-only journey that selects Northwind with Enter and verifies the selected workspace and current-page state.
- Added an API gateway permission-refusal assertion: an organization in another workspace returns no branding, and the query remains scoped to the principal's workspace.
- Corrected logo accessibility discovered by the browser checks: the actual logo alternative is exposed to assistive technology, while the initials fallback is named with the organization name.

## Scope and remaining integration boundary

These checks currently run against the isolated T2 mock-backed preview, not a live signed-in workspace. The repository still has no web authentication/session principal or branding API read route, so the permission check proves the T1 gateway's workspace-scoping behavior; it does not claim an application role/permission policy. The AC4 number is a local production-build measurement, not a deployment-wide load-test result. Re-run against seeded authenticated preview data when those dependencies are available. This task does not implement later story tasks.
