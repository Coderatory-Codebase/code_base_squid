# 01.1.04-S1-T2 — Build the Server Component view for organization branding

## Task understanding

Build a server-rendered organization branding page. Its server component loads branding before rendering and sends only display data to the small client-side logo fallback. The view needs an organization list and selected workspace header, default initials/colour when branding is absent, a resilient fallback when a logo URL fails, and useful empty/error states. No browser-side data fetch or domain import in a client component.

## Repository dependency found

T1 added a workspace-scoped branding gateway under `servers/api/features/workspace`, but `apps/web` is architecturally prohibited from importing `servers/api`. The API currently has no authenticated branding read route, and the web app has no session/principal capability. Passing a workspace ID from a URL or hard-coding it into a live API request would bypass the principal boundary.

For isolated acceptance checks, T2 keeps a **web-owned test fixture** behind `ORGANIZATION_BRANDING_T3_FIXTURES=enabled` plus an explicit `fixture=demo` or `fixture=load` query. It is called only by the Server Component and does not connect to or write to MongoDB. The normal page has no mock-data fallback; it uses the temporary Mongo-backed adapter only when explicitly enabled, otherwise it shows unavailable until the owning auth/session and API dependencies are merged. Keep the page and display components when replacing temporary support.

## Implementation plan

- Add a route at `apps/web/app/(app)/workspace/organization-branding/page.tsx`.
- Add a feature-owned server view and a minimal client logo component that receives display-only props.
- Keep deterministic fixture reads on the server for tests only, including empty and unavailable outcomes, without browser fetching.
- Keep preview fixtures isolated under `apps/web/features/organization-branding/support/`.
- Record the live seeded-workspace journey as follow-up verification: it requires authenticated preview deployment. T3 adds a separate mock-only 50-organization fixture for a local 200-open p95 check.

## Implementation completed in this repository

- Added the dynamic route at `apps/web/app/(app)/workspace/organization-branding/page.tsx`.
- The async Server Component reads before rendering and passes serializable view data to the UI. There is no browser-side data fetch.
- The list and workspace header share organization logo/accent values. Missing branding falls back to two-letter initials and `#4B5563`; the logo client island shows the same initials if its image fails and has no domain imports.
- Added clear empty and unavailable states. The unavailable view has a retry action; the empty view offers a reload action without sample data.
- Added four behavior tests for the server reader path, unbranded defaults, empty selection and unavailable reader.
- `pnpm --dir apps/web exec tsx --test tests/organization-branding-page-data.test.ts`, web typecheck, web lint, and web production build pass. The route was opened locally; Acme, Northwind and the broken-image fallback rendered as expected.

## T2 task-brief checklist

The imported T2 Done When is: render from a gateway query with no client-side fetch; provide empty and error states; do not import a domain module from a client component. Its five implementation steps map to the code as follows:

1. Route segment exists at `apps/web/app/(app)/workspace/organization-branding/page.tsx` (this repository has no `src/` prefix).
2. The Server Component reads through the web-owned gateway interface before rendering. It does not fetch from a client component. The API gateway cannot yet be called from web because the authenticated API read route/session is not present.
