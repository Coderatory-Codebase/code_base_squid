# 01.1.03-S2-T6 — Organization settings acceptance checks

## Automated checks

Added `servers/api/features/workspace/tests/organization-settings.acceptance.test.ts`.
The suite exercises the real API route and a disposable MongoDB instance and checks:

- An owner can update settings and receives the normalized values with an incremented version.
- An invalid time zone is rejected without changing persisted settings or version.
- A stale version returns `409` with the current settings and version.
- A member is refused with `403` and cannot mutate settings.
- The successful update emits a structured boundary signal with the feature label, outcome, and duration.

The member refusal is in the same acceptance suite. Existing policy tests separately cover
guests, API keys, and commands without a policy decision.
