# 01.1.03-S1-T4 — Organization settings operational signal

## Signal contract

The workspace settings gateway emits a structured completion event for successful reads
and a structured error event for failed reads. Both events carry `module: workspace`,
`feature: organization-settings`, `operation: read`, and the principal's `workspaceIds`.
The completion event includes `outcome` and `durationMs`; failures also include a reason.

## Failure-path evidence

`servers/api/features/workspace/tests/organization.gateway.test.ts` seeds a malformed
time-zone value, verifies the settings read rejects, and asserts one error signal with
the workspace/module labels, failure outcome, duration and reason.

## Operational dependencies

- The Grafana dashboard definition now includes organization-settings read volume by
  outcome, failed-read count, and p95 duration panels. It filters the structured log fields
  `feature=organization-settings` and `operation=read`.
- The 700 ms p95 threshold is a proposal recorded in
  `enablers/observability/workspace/organization-alert-policy.json`; it is not approved.
  The workspace on-call rotation must record its approver and date before paging is enabled.
- The dashboard JSON has not been imported into a deployed Grafana instance. Its visible
  production delivery still depends on the central Loki datasource and dashboard import.
- The failed-read test proves the emitted error log locally. It does not prove delivery to
  a deployed dashboard.
