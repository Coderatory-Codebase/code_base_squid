# 02.1.02-S1-T3 — Automate Story Acceptance Checks

## Scope

Story: **02.1.02 Invite people to a workspace by email** (`02.1.02-S1`).

This task verifies the Story’s invitation behaviour without changing its acceptance
criteria. The work is application scope: invitation feature code in
`servers/api/features/identity`, its feature-owned tests, and the web invitation
surface tests.

## Known acceptance coverage

The existing feature-owned service suite names six Story behaviours, but its fake gateway
does **not** meet the exported story's required Integration, Contract, or Load methods:

1. Create one pending invitation with a seven-day expiry and return its link once.
2. Persist only a SHA-256 token hash.
3. Replace a pending invitation and invalidate its earlier link, including when two
   invite commands race to create the first pending record.
4. Refuse an unauthorized invitation, avoid persistence, and audit the refusal.
5. Reject invalid email input without persistence.
6. Run the stated 20 invitations/second for 10 minutes and prove the production p95
   bound with the required load environment.

The task also requires `TC-02.1.02-S1-X-accessibility`. Its required verification is a
recorded keyboard/screen-reader walk in a preview deployment. A server-rendered markup
assertion is supplementary only and cannot mark this case complete.
