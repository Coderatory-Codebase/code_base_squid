# 02.1.02-S1-T2 — Invitation server-rendered view

## Scope and contract

The invitation surface must be server rendered, consume a real scoped invitation query,
avoid client-side data fetching/domain imports, and provide useful empty and failed
states. The API composition must expose the list boundary the page calls.

## Plan

1. Compose an explicit authenticated-principal boundary and invitation list route.
2. Connect the server-only web query to that boundary.
3. Add the empty-state next action and an actionable failed-state retry.
4. Verify route and server-rendered view behaviour through their intended boundaries.

## Audit result

The page is server rendered and has loading/empty/error components, but it calls an API
list endpoint that is not registered in API bootstrap. No resolved principal/policy
boundary exists for that endpoint, and the empty state lacks the requested next action.
This task is not complete.

## 2026-10-08 implementation update

- Added a “Browse organizations” next action to the empty state and a markup assertion
  for the destination.
- Registered `GET /identity/user-invitations`. The web server query forwards its existing
  HttpOnly `workspace_session` as a bearer token. API composition resolves the user, finds
  exactly one active workspace membership, and dispatches a list command through the
  command bus. Identity binds the command to the central `workspace.invitation.manage`
  ability and re-reads the active role/guest fields before allowing owner/admin access.
  Response fields exclude token hashes and inviter identifiers. Query filters accept only
  the supported invitation statuses.
- Added focused tests for owner/admin allow, member/guest refusal, secret-free list shape,
  and invalid/repeated status filters. These pass; they use explicit test doubles and do
  not replace the required database-backed HTTP test.
- Still incomplete: users with multiple active workspaces receive the existing 409
  selection-required outcome but the web page has no workspace selector. A real Mongo
  route/render test and the write action remain pending.
