# 02.1.02-S1-T1 — Scoped invitation gateway

## Scope and contract

Identity owns `user_invitations`. Every invitation read/write must accept a resolved
principal, inject `workspaceId` last, and exclude `deletedAt` by default. The task is
complete only with real-Mongo evidence of tenant isolation, the intended query index,
and the repository's current ownership/governance record.

## Plan

1. Verify a replica-set Mongo integration environment and use it for gateway tests.
2. Prove cross-workspace reads return no rows and soft-deleted rows are excluded.
3. Prove the scoped pending-list query uses its covering index.
4. Record the collection owner and retention/index design in the task evidence.

## Audit result

The feature gateway scopes filters correctly and replacement of a pending invitation
updates the existing record rather than creating a second pending record. The required
real-Mongo cross-tenant query, explain-plan, collection allow-list, and migration
evidence remain unavailable; this task is not complete.
